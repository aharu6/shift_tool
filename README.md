# shift_tool

薬剤部向けの月次シフト作成ツールです。mode1では当直・出勤を決め、mode2では確定済みの出勤表を読み込み、専属・兼務業務を割り当てて週間Excelを作成します。

## mode2：週間配置

`uv run main.py` でモード2を選び、対象年月、スタッフ条件、希望表、mode1の出勤表（`work_status_wide_YYYY_MM.xlsx`）を指定します。スタッフ条件には `ICT` 列が必要です。出勤表の空欄・`◎`は出勤、その他の記号は非出勤として扱い、当直の `◎` は週間表に表示します。

出勤者の専属配置と兼務配置を同時に求解し、`result/weekly/` に週ごとのExcelを保存します。同じ年月・週番号の既存ファイルは上書きされます。人数の不足・余剰はソフト制約として求解時に警告し、監査などの必須制約が両立しない場合は解なしになります。制限時間内に見つけた解は最適解とは限らないため、必ず人手で確認してください。

病棟・調剤室の目標人数は曜日別・午前午後別に設定しています。マスター管理中の時間帯は原則として専属業務の人数から除外し、土曜午後の化療担当は例外として化療人数に含めます。調剤室人数には半日希望と各兼務を反映します。昼の役職者会議と病棟カンファレンス、16:30からの薬剤部連絡会は調剤室人数に含めます。薬剤部連絡会は出勤者が参加し、他の午後業務との重複を許容します。

- ICT回診は祝日以外の火曜午後に、`ICT` が有効で出勤可能なスタッフ全員の配置を優先します。他の業務と両立できなければ未配置を警告します。
- 祝日以外の土曜は、化療・調剤室の両資格を持つ出勤者を1〜2名配置します。午前は調剤室と化療兼務、午後は化療専属として週間表に表示します。候補が0人なら解なしです。
- 土曜の入退院センター担当者は、午前の入退院センターと午後の調剤室に表示します。調剤室の目標人数には午前・午後とも含めます。
- マスター管理の希望はファイル選択後にスタッフ名（フルネーム）・日付・`AM`／`PM` を繰り返し入力し、スタッフ名を空欄にして終了します。名前の半角・全角スペースは照合時に削除します。マスター管理の資格、出勤日、時間帯を検証します。他の必須業務との競合で解なしになった場合、希望を再入力できます。土曜化療の午後と薬剤部連絡会以外の同時間帯業務との重複は禁止します。

日祝は課長・部長をそれぞれの所属へ配置し、それ以外は調剤室を優先します。調剤室の資格がない場合は資格のある所属先に配置します。病棟人数などの目標は日祝には適用しません。

## 実行方法

Python 3.12 以降、[uv](https://docs.astral.sh/uv/) を前提としています。リポジトリのルートで依存関係を同期して起動してください。

```bash
uv sync
uv run main.py
```

通常起動では以下の順で入力します。

1. 対象年を入力
2. 対象月を入力（1〜12）
3. スタッフ条件ファイルを選択
4. 前月シフトを選択（月初の連携に使用）
5. 集計する過去の当直表を含むフォルダを選択
6. 12月または1月の場合、前年の同月のシフト表とスタッフ条件ファイルを選択
7. 希望リストファイルを選択

入力確認後、当直の最適化が実行されます。探索時間は 300 秒、相対ギャップ上限は 3% で設定されています。

テスト用の固定入力で起動する場合は、次のコマンドを使います。

```bash
uv run -m shift_tool.tests.main_test
```

このテスト用スクリプトは対象年月を2026年10月に固定し、入力ファイルに開発環境固有の絶対パスを指定しています。別の環境ではスクリプト内のパスを変更してください。

## 実際の処理フロー

`main.py` の `create_shift_schedule()` では、以下の順で処理を行います。

- 年月の入力
- `jpholiday` による祝日取得
- スタッフ条件ファイルの読み込み
- 前月シフトの読み込みと当直履歴の抽出
- 選択フォルダ内の当直回数の集計
- 前年12月/1月の連携用履歴の読み込み
- 希望リストの読み込みと名前の正規化
- `ShiftOptimizer` による当直変数・当直制約の初期化
- CP-SAT による最適化
- 結果のCSV出力

mode1の `ShiftOptimizer.apply_all_constraints()` は当直・出勤の制約を扱います。週間配置は別途mode2で行います。

mode1の日曜・祝日は、調剤室に対応可能な出勤者を通常4人とし、休日が連続する場合は前日の目標に応じて4人・7人を交互にします。12月30日〜1月3日は専用ルールを優先し、12月29日が日曜なら12月30日は7人、それ以外は4人として、以降1月3日まで交互にします。人数は必須で、不足・超過すると解なしになります。午前のみ・午後のみの出勤は0.5人として数え、外来・学会・研修は人数から除外します。

外来資格のあるスタッフを除き、出勤日と当直明けを合わせて連続6日までとし、7日以上連続しないことは必須です。前月末も判定に含め、研修・学会は出勤として数えます。希望などの他の必須条件と両立しない場合は解なしになります。
前月の勤務・当直明けと今月の出勤・当直・研修・学会希望から月またぎの7日連続が確定する場合、求解前に対象者と7日間の日付・理由を表示して中止します。ほかの条件によって初めて確定する競合は、この事前チェックでは検出できません。

平日・土曜の人数は各セクションと調剤室の必要人数を合算し、調剤室と重複する入退院センター、および土曜の化療担当を差し引いたソフト目標です。学会・研修は出勤扱いですが配置人数に含めず、半日出勤は0.5人として数えます。不足・超過があっても解を許容します。

mode1では役職者会議・病棟担当者カンファレンス・臨床薬剤課役職者会議・薬審の対象者について、休み希望や学会・研修を除き、会議日の出勤をソフト制約で優先します。第4金曜の薬剤部連絡会のために出勤を増やすことはせず、mode2で出勤者を参加させます。ポリファの開催日はmode2で確定するため、mode1では開催日に連動した当直回避を適用しません。

実行ログは `logs/shift_run_YYYYMMDD_HHMMSS.txt` に出力されます。
ログには日ごとの当直候補ペア数、当直希望者ごとの候補数・除外理由、希望日の同時割当診断も記録されます。

## 入力ファイル

### 1. スタッフ条件ファイル

- ファイル選択ダイアログで Excel を選択
- `member_list` シートを使う
- `skiprows=1` で先頭行を読み飛ばす
- `Name` 列と各スタッフの属性（Floor / Floor2 / Floor3 など）を正規化して利用する

### 2. 希望リスト

- Excel ファイルを選択
- `skiprows=[1]` で2行目を読み飛ばす
- 最初の列を `Name` に置き換える
- 1〜31 日までの列に絞って扱う
- 休み希望・当直不可・出勤希望・会議希望などを読み込む

### 3. 前月シフト

- 前月のシフト表 Excel を手動で選択
- `_load_previous_month_shift()` が読み込み、`-1`〜`-8` の過去8日間を変換して取り込む
- これにより、月初の当直可否・休み回避の制約に前月末の勤務が反映される
- 前月表の日付セルの空欄は、月またぎの連続出勤を計算する際に通常出勤として数える

### 4. 当直履歴フォルダ

- 当直表の Excel をまとめたフォルダを選択
- フォルダ直下の `*.xlsx` を対象に、日付列の `◎` をスタッフごとに集計する。集計期間は選択するファイルで決まり、月の不足や期間は自動検証しない
- ファイル名の `2026_08`、`2026-08`、`2026年8月`、`2026年08月` のような年月を認識する。月が1桁でも同じ年月として扱い、ファイル名自体は変更しない。年月が判定できない場合は端末で入力する
- 異なる表記でも同じ年月のファイルが複数ある場合は、集計する1ファイルを端末で選択する。`0` で中止できる
- フォルダ内にファイルがない場合や読み込めないファイルがある場合は、履歴が不完全な状態で続行するか確認する
- 前月シフトは別途選択し、前月の当直回数を集計する。累計に前月を含めたい場合は、当直履歴フォルダにも前月のファイルを含める

### 5. 年末年始の履歴

- 12月作成時は前年12月、1月作成時は前年1月のシフトExcelと同じ月のスタッフ条件Excelをそれぞれ選択する
- 前年の12月30日・31日または1月1日〜3日の勤務者を抽出し、該当日の出勤・当直制約に利用する。空欄・当直明けを含め、前年の外来所属者・休暇・研修・学会は除外する
- 対象日列やスタッフ条件が不正な場合、またはファイル選択を中止した場合はエラーで終了する

## 主な制約と最適化内容

現在有効な当直モデルでは、主に以下の要件を `CP-SAT` に設定します。

- 毎日1組の当直ペアを割り当て、同じスタッフが同日に複数のペアへ入らない
- 当直希望（希望値8）はハード制約として扱い、希望者を希望日の当直ペアに必ず含める
- 当直不可・休職・休み系希望を反映し、同性かつ別フロアのペアを割り当てる
- 当直間隔、月間回数の上限、前月回数を踏まえた回数調整
- ペアの条件や会議・回診前後の当直回避
- 当直回数の偏りを抑える目的関数

主任以上・外来資格のあるスタッフ・当直不可のスタッフは当直回数の公平性評価から除外します。前月1回なら今月2回、前月2回以上なら今月1回をソフト目標とし、選択した履歴と今月の当直回数の差も抑えます。どちらも必須ではなく、他の制約との兼ね合いで目標を満たさない場合があります。

連休希望などにより、当直日とその翌日の明けを置ける局所的な候補ペアが月内にないスタッフは、当月の当直最低1回の対象から除外します。休み・育休・有給・慶弔休暇・産休・特別休暇・指定休・夏休みの希望日は当直にも明けにも充てません。月末の翌日は翌月の希望を読み込まないため、この候補判定には含まれません。毎日1ペアの当直は引き続き必須です。

当直希望と当直不可日、翌日の希望、月間回数上限、7日間隔、前月当直履歴などのハード制約が両立しない場合、最適化結果は `INFEASIBLE` になります。同日に3人以上の希望がある場合など、事前検証で検出できる競合はソルバー実行前にエラーとして通知します。局所的な候補があっても、他の制約との組み合わせにより月1回を割り当てられない場合には、最低回数は自動で免除されません。

実行ログの `[局所ハード条件後ペア数]` は、同性・別フロア・当日/翌日の希望・当直資格・月上限・当直間隔・前月履歴を基にした日ごとの候補数です。`[当直希望同時割当]` は希望日をまとめて割り当てられるかの診断で、全日程の他の制約を含む最終的な成立保証ではありません。候補があるのに最終モデルが `INFEASIBLE` の場合は、候補の重複や通常日の割当との競合を追加で調べてください。

当直制約の詳細は `optimizer/mode1/night_shift/oncall_constraints.py` を参照してください。

## 出力ファイル

最適化に成功すると `result/` 配下に以下を出力します。

- `Shift_YYYY_MM.csv`  
  スタッフ・日付ごとの明細。当直結果を記録する。専属業務・兼務業務は現在自動配置されず、既定値のまま
- `Shift_wide_YYYY_MM.csv`  
  専属業務欄を日付横持ちにした表。現在は専属業務が最適化されないため、完成した勤務表としては使用できない
- `Shift_cleaned_YYYY_MM.csv`  
  転記形式に整形した表。現在は専属業務が最適化されないため、完成した勤務表としては使用できない
- `oncall_shift_long_YYYY_MM.csv`  
  当直の縦長データ
- `oncall_shift_wide_YYYY_MM.csv`  
  当直の横長表と当直回数。希望休は希望内容で表示し、それ以外の非出勤日は「指」で表示
また、実行ログは `logs/shift_run_YYYYMMDD_HHMMSS.txt` に書き出されます。

mode1は週次Excelを出力しません。mode2の求解に成功すると `result/weekly/` に出力します。

## 備考

- 実行時にファイル選択ダイアログが出るため、対話型で処理を進める前提です。
- 生成物は `result/` 配下に保存されます。`Shift_cleaned_YYYY_MM.csv` などは専属業務が未配置の状態なので、完成した勤務表として次月連携に使う前に内容を確認してください。
- テスト用スクリプトは固定の年月・入力パスを使います。通常の対話起動は `uv run main.py` を使用してください。
